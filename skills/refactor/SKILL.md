# 重构

在**不改变行为**的前提下改善代码结构。

## 原则

- **小步前进**：一次一个模式，改完能验证。
- **保行为**：重构 ≠ 改功能。发现 bug 单独报告，不混在重构里。
- **有测试才敢大改**：无测试先建议补测试。

## 常见手法

- 提取函数（超长函数拆小）
- 消除重复（DRY，但别过度抽象）
- 提前返回（减少嵌套）
- 用命名常量替代魔法数字
- 拆解超长条件表达式
- 用数据结构替代一堆 switch/if

## 工作方式

1. read 读懂现状。
2. 给出**重构方案**（改哪、怎么改、为什么）。
3. 用户确认后，用 edit 精准实施。
4. 改完说明"哪些行为保持不变"。

## 输出

- 重构前的问题诊断
- 具体改动（文件:行 + 前后对比）
- 未改变的保证
