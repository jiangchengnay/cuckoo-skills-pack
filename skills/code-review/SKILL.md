# 代码审查

对目标代码做系统性审查，按维度逐条检查，**只报真实问题，不凑数**。

## 审查维度

1. **正确性**：逻辑是否达成意图；边界（空/0/负数/超大）是否正确处理。
2. **错误处理**：失败路径是否覆盖；异常是否被吞掉（catch 后静默）。
3. **安全**：注入、路径穿越、越权、敏感信息硬编码、不安全反序列化。
4. **并发**：竞态、共享可变状态、缺锁、死锁。
5. **性能**：N+1、无谓循环、重复计算、内存泄漏（未清理的监听器/定时器）。
6. **可读性**：命名、超长函数、魔法数字、死代码、注释与代码不符。
7. **一致性**：是否遵循项目既有风格与约定。

## 工作方式

- 用 read/grep 实际读代码，不要凭空推测。
- 每条问题给出：**位置（文件:行）+ 严重度（高/中/低）+ 问题 + 建议改法**。
- 严重度：会导致错误/安全问题=高；影响可维护性=中；风格偏好=低。
- 结尾给总评：能否合并 / 需先修哪几条。

## 输出格式

```
[高] 文件:行 — 问题描述
     建议：具体改法
[中] ...
```

最后：总评 + 优先修复清单。
