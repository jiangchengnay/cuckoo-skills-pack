# 安全自查

对目标代码/配置做安全检查，聚焦**真正可被利用**的问题。

## 检查清单

1. **注入**：SQL/命令/模板/路径注入；是否拼接未过滤的用户输入。
2. **密钥泄露**：硬编码 token/password/私钥；日志打印敏感信息。
3. **路径穿越**：文件路径来自外部且未校验 `..`。
4. **鉴权**：接口漏鉴权；越权访问他人资源。
5. **反序列化**：不安全反序列化（eval、pickle、yaml.load）。
6. **依赖**：已知漏洞版本（有 lockfile 就查）。
7. **XSS/CSRF**（Web）：未转义输出、缺 CSRF token。

## 规则

- 只报**可利用**的，不报"理论上可能"的。
- 每条给：位置 + 攻击场景 + 修复。
- 区分「高危（可直接利用）」和「加固建议」。

## 输出

```
[高危] 位置 — 攻击场景 — 修复
[加固] 位置 — 建议
```

无问题则明确说"未发现可利用问题"。
