# 全能技能包（cuckoo-skills-pack）

为 [Cuckoo Code](https://github.com/wangyongpeng90/cuckoo-code) 提供一组通用开发技能，让 AI 助手在常见开发场景下表现得更专业、更可靠。

## 为什么需要这个插件

Cuckoo Code 默认的 AI 助手已经很强，但在特定场景下（代码审查、写测试、排查 bug 等）缺乏结构化的方法论。本插件为这些场景提供经过打磨的「技能」——每个技能都是一套完整的操作指南，告诉 AI 该怎么想、怎么做、怎么输出。

**装完即用，无需配置。** 纯提示词实现，不含任何可执行代码，启用时不会弹出安全警告。

## 包含技能

| 技能 | 触发场景 | 核心能力 |
|---|---|---|
| code-review | 要求审查代码 | 7 维度系统审查，只报真实问题 |
| commit-message | 要写 commit | 生成 Conventional Commits 规范提交信息 |
| explain-code | 问"这段代码干嘛的" | 从整体到细节讲解，标注可疑写法 |
| refactor | 要重构 | 不改变行为的前提下改善结构 |
| security-check | 关心安全 | 检查注入、密钥泄露、路径穿越 |
| write-tests | 要写测试 | 优先覆盖失败路径和边界 |
| generate-docs | 要写文档 | 生成注释、README、API 文档 |
| debug-assist | 遇 bug | 系统化排查：复现→定位→根因→修复 |

## 技能详解

### code-review — 代码审查

对目标代码做系统性审查，覆盖 7 个维度：

1. **正确性** — 逻辑是否达成意图；边界（空/0/负数/超大）是否正确处理
2. **错误处理** — 失败路径是否覆盖；异常是否被静默吞掉
3. **安全** — 注入、路径穿越、越权、敏感信息硬编码
4. **并发** — 竞态、共享可变状态、缺锁
5. **性能** — N+1、无谓循环、内存泄漏
6. **可读性** — 命名、超长函数、魔法数字、死代码
7. **一致性** — 是否遵循项目既有风格与约定

输出：每条问题标注位置（文件:行）、严重度（高/中/低）、问题描述和建议改法；最后给总评和优先修复清单。

原则：只报真实问题，不凑数。宁可少报，不可误报。

### commit-message — Git 提交信息

读 git diff 和 git status，归纳改动意图，生成 Conventional Commits 规范的提交信息。

支持类型：feat / fix / docs / style / refactor / perf / test / chore / ci / build / revert。

规则：标题 ≤ 50 字、中文、动宾结构；一个 commit 只做一件事；正文解释"为什么"。

### explain-code — 解释代码

从整体到细节讲解代码：

1. 一句话概括 — 这段代码解决什么问题
2. 输入 → 处理 → 输出 — 数据怎么流动
3. 关键步骤 — 按逻辑分段讲解
4. 易忽略的细节 — 边界处理、隐式约定、坑
5. 依赖关系 — 调用了哪些外部函数/模块

遇到可疑写法会标注「注意」。

### refactor — 重构

在不改变行为的前提下改善代码结构。常见手法：提取函数、消除重复、提前返回、命名常量、拆解超长条件。

原则：小步前进、保行为、有测试才敢大改。

### security-check — 安全自查

聚焦真正可被利用的安全问题：

- **注入** — SQL/命令/模板/路径注入
- **密钥泄露** — 硬编码 token/password/私钥
- **路径穿越** — 文件路径来自外部且未校验
- **鉴权** — 接口漏鉴权、越权访问
- **反序列化** — eval、pickle、yaml.load
- **依赖** — 已知漏洞版本
- **XSS/CSRF**（Web）

输出：区分「高危（可直接利用）」和「加固建议」。

### write-tests — 编写单测

核心原则：

- 真实集成优先，只 mock 外部边界（网络、文件系统、时间）
- 不写深 mock 测试（不断言"mock 被调用几次"）
- 优先覆盖失败路径和边界值

步骤：读被测代码 → 列行为清单 → 设计正常+失败用例 → 遵循项目测试风格 → 跑一遍确认通过。

### generate-docs — 生成文档

生成准确、有用的文档：函数注释、README、API 文档、架构说明。

原则：先读代码再写，文档必须与代码一致；写"为什么"和"怎么用"，不重复代码本身能说明的。

### debug-assist — 错误排查

系统化定位问题根因：

1. 读完整错误 — 堆栈、错误码、上下文都要看
2. 复现 — 用最小步骤复现
3. 缩小范围 — 二分法确定哪步开始出错
4. 找根因 — 追问"为什么"直到源头
5. 验证修复 — 改完重测原场景

常见根因：时序/竞态、空值、类型不符、编码/路径、依赖版本、环境差异。

## 安装

### 方式一：从插件市场安装（推荐）

1. 打开 Cuckoo Code
2. 进入「插件」页面
3. 搜索 cuckoo-plugin
4. 找到「全能技能包」点击安装
5. 启用插件

### 方式二：手动克隆

    git clone https://github.com/jiangchengnay/cuckoo-skills-pack.git ~/.cuckoo/plugins/cuckoo-skills-pack

安装后在插件页启用即可。

## 特性

- **纯提示词，零执行** — 不含任何可执行代码，启用时不会弹出"含可执行内容"的安全警告
- **开箱即用** — 装完即生效，无需配置
- **无外部依赖** — 不依赖任何外部服务或 npm 包
- **标准插件格式** — 遵循 Cuckoo Code 插件规范

## 常见问题

**Q：为什么启用时没有安全警告？**
A：本插件只包含技能（skills），不含任何可执行代码。技能是纯提示词，不会在本机运行第三方代码。

**Q：技能和子代理有什么区别？**
A：技能是"操作指南"，在当前对话上下文中生效；子代理是"独立助手"，在独立上下文中执行任务后返回摘要。

**Q：怎么知道技能生效了？**
A：技能会在相关场景下自动被 AI 引用。你也可以直接说"用 code-review 审查这段代码"来显式触发。
